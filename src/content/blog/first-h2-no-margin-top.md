ブログやWebメディアの記事詳細を実装する時に、h2の`margin-top`を大きく取ることはよくある。それによって、他のセクションとの境界線がわかりやすくなる。

しかし、記事タイトルのすぐ下に「はじめに」のような見出しが来る構成では、見出しの上が空きすぎてしまう。これを解消してみる。

なお、現在作っている記事詳細画面が、WordPress → Astroへの以降に際してデザインを修正するもので、クラス名にはそれ由来の命名があることを事前にご承知おきいただきたい。

## やりたいこと

本文エリアのなかで、いちばん最初に現れる見出しがh2なら、上マージンだけ0にする。

2つ目以降のh2は、これまでどおり余白を大きくしてよい。

## 実装

見出し共通では、たとえばこうしている。

```css
.blog-body :where(h2) {
  font-size: 1.5em;
  margin: 48px 0 24px;
}
```

そのうえで、先頭h2だけ上を打ち消す。

```css
/* 本文の先頭が h2 のときは見出し上の余白を入れない */
.blog-body > :where(h2):first-child,
.blog-body :is(.wp-content, .md-content) > :where(h2):first-child {
  margin-top: 0;
}
```

ポイントは次の3つだ。

**`:first-child`** … その親の最初の子要素であること。前に`p`や`div`があれば、h2は対象外になる。

**子セレクタ`>`** … ラッパーの「直下」のh2だけを指す。本文の途中のh2には効かない。

**`:where(h2)`** … 詳細度を増やしすぎずにh2だけを指定する。

## なぜセレクタが一段増えるか

記事ページのDOMは、だいたい次のどちらかになる。

1. 見出しが`section`（本文ラッパー）の直下にある
2. WordPress由来のHTMLが`div`の中に入っている

さらに、アソシエイト注記のような短いブロックが本文の前に置かれることもある。このとき、**「先頭のh2」はセクションの直下の子ではない**。ラッパー要素の**最初の子**としてh2が来る。

だから、

- 直下パターン用に`> h2:first-child`
- ラッパー内パターン用に`.wp-content > h2:first-child`（Markdownや別形式のラッパーも同様）

の両方を書く必要がある。

## 当てはまらないケース

先頭にリード文や引用、注記があると、h2は「最初の子」ではなくなる。そのときは48pxの上余白が残るのは意図どおりだ。

「注記のあとも、最初の見出しなら詰めたい」まで広げるなら、`:first-child`だけでは足りない。`:has()`で「このh2より前に兄弟の見出しがない」といった条件を組み直す必要がある。

## ほかの書き方

| 方法 | 向いている場面 |
| --- | --- |
| `h2:first-child` | 本文の最初の要素が確実にh2のとき |
| `h2:first-of-type` | 同じタグの兄弟のうち最初（前に別タグの兄弟があると期待とずれる） |
| `:has()` | 「最初の見出し」など、より抽象的な条件 |
| テンプレートでclassを付与 | CSSが複雑になりすぎるとき |

小さなサイトなら、**直下の`> h2:first-child`と、ラッパー内の`> h2:first-child`の二本立て**で十分なことが多い。

## まとめ

記事見出しに共通の`margin-top`を付けると、**本文先頭のh2だけ妙に空く**ことがある。**親直下、または本文ラッパー直下で`h2:first-child`なら`margin-top: 0`**と書けば、2見出し目以降の区切りは保ったまま、タイトル直後だけ詰められる。

DevToolsで本文ラッパーを開き、最初のブロックがh2かラッパー内のh2かを一度確認してから、セレクタを足すと安全だ。[蓼食う本の虫](https://tadeku.net/)のAstro版でも、同じ考え方で直した。
